### [waves] Enemies-per-wave count formula — 🟡 partial
- **Web** (src/components/game/LocalEnemySystem.tsx:529-531): getEnemiesForWave(wave) = Math.floor((3 + (wave*2)) * 1.5). NOTE it uses wave*2, not (wave-1)*2. Wave1=7, Wave2=10, Wave3=13, Wave4=16, Wave5=19 — a strictly increasing linear ramp. (GAME_CONFIG.WAVES BASE_ENEMIES:3/ENEMIES_PER_WAVE:2/ENEMY_MULTIPLIER:1.5 exist at gameConfig.ts:67-75 but are NOT imported — LocalEnemySystem hardcodes the literals.) Same formula duplicated in WaveDisplay.tsx:77 for the 'N dogs this round' text.
- **Native** (game/systems/WaveSystem.cpp:408-421 + game/systems/WaveDifficulty.hpp:86-128 + game/CatAnnihilation.cpp:203-210)
- **Gap**: Native uses a completely different formula AND much lower counts. Live config override (CatAnnihilation.cpp:204-205) sets baseEnemyCount=3, enemyCountMultiplier=2.0, then WaveDifficulty::calculateEnemyCount applies a dense/sparse sine overlay: floor(3 + (N-1)*2 + 2*sin(2*pi*N/3)), min 1. Wave1=4, Wave2=3, Wave3=7, Wave4=10, Wave5=9. Two divergences: (1) counts are far lower than web (4 vs 7 at wave 1); (2) the sine overlay makes counts NON-monotonic — wave 2 (3 dogs) spawns FEWER than wave 1 (4 dogs), which web never does. To match web this must be floor((3 + wave*2)*1.5) with amplitude 0.

### [waves] Win condition (endless vs wave-5 cap) — 🟡 partial
- **Web** (src/components/game/LocalEnemySystem.tsx:701,744): ENDLESS. On wave completion nextWave = currentWave + 1 with NO upper bound and NO victory/win state anywhere. The survival mode runs infinitely until the player dies. There is no 'you win' screen.

There is NO mouse camera control at all.
- **Native**: `PlayerControlSystem::init` enables follow-yaw + the (0, 8.4, 10.5) offset for ALL play under `WebParity::kEnabled` (not just --autoplay), position hard-snaps in locked-behind mode, and `processMouseLook` early-returns (mouselook retired). - **Native** (game/systems/EnemyAISystem.cpp:60-83)
- **Gap**: Native uses an Idle->Chasing state machine: updateIdleState only transitions to Chasing when distance <= aggroRange. But DogEntity::create OVERRIDES aggroRange to the per-type stat (DogEntity.cpp:361,391) = 15 (Dog/BigDog), 18 (FastDog), 25 (BossDog) — contradicting the EnemyComponent.hpp:38 default of 80 and its own comment ('generous so dogs always close regardless of spawn radius'). So virtually every wave dog spawns 25-40m out with an aggro radius of 15-18m: it stays in AIState::Idle and never chases until the player walks within 15m of it. Web dogs relentlessly swarm from spawn; native dogs passively wait. In the survival arena this reads as broken enemies that ignore a stationary player.

Zustand = UI/static (player position/health, inventory, catStats, weaponSkills, storyMode, quests, dayCycle).

- **customization-appearance:** Web CatCustomizationContext + CustomizableCatMesh + clanCustomizations; native cat_customization + accessory_data. Cosmetic system, cross-cutting.
- **persistence-save-load:** Web localStorage (gameStatePersistence: mode/story/player progress); native SaveSystem (5 slots, autosave) + Continue. Adjacent to gameflow-states but a distinct subsystem.
- **story-mode-systems (P3 cluster):** NPC/Dialog/Quest/Clan/Merchant/StorySkills/Territory/Compass/QuestBook exist on BOTH sides but as a large self-contained cluster only loosely under "progression." Recommend one P3 domain rather than scattering across planned domains.
